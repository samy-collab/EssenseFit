1. Visao geral

O Essence Fit e um sistema full-stack para uma loja virtual de moda fitness feminina. A proposta combina e-commerce, acompanhamento de atividades fisicas, sistema de pontos e recompensas por cupons de desconto.

A aplicacao atende dois perfis principais: clientes, que compram produtos, fazem check-ins e resgatam cupons; e administradores, que gerenciam produtos, pedidos, cupons e dados gerais.

Recursos principais

  • Autenticacao com JWT.
  • Catalogo de produtos por estacao.
  • Carrinho e criacao de pedidos.
  • Check-in Fitness liberado apos primeira compra.
  • Pontuacao por atividades fisicas.
  • Resgate de cupons com pontos.
  • Perfil de usuario com foto e integracao Strava.

Perfis de acesso

  • ADMIN: gerencia produtos, pedidos, cupons e check-ins.
  • CUSTOMER: compra produtos, acompanha pedidos, faz check-ins e resgata cupons.

2. Tecnologias usadas

Backend

  • Go como linguagem principal.
  • Gin para API HTTP.
  • GORM para acesso ao banco.
  • PostgreSQL como banco relacional.
  • JWT para autenticacao.
  • bcrypt para hash de senhas.

Frontend e infraestrutura

  • React 18 com TypeScript.
  • Vite para desenvolvimento e build.
  • Tailwind CSS para estilos.
  • Axios para consumo da API.
  • React Router para navegacao.
  • Docker Compose para frontend, backend e banco.

3. Arquitetura geral

O projeto e dividido em tres partes principais: frontend React, backend Go e banco PostgreSQL. O frontend conversa com a API usando chamadas HTTP. O backend aplica regras de negocio, autentica usuarios, manipula arquivos de upload e persiste dados no banco.

  • Frontend: telas, contexto de autenticacao, carrinho, chamadas para a API e experiencia da usuaria.
  • Backend: rotas, handlers HTTP, servicos de negocio, repositorios e modelos.
  • Banco: tabelas criadas por migrations SQL versionadas em backend/config/migrations.
  • Docker: orquestra PostgreSQL, API e frontend para ambiente local.

5. Principais pastas do backend

  • backend/config: configuracao da aplicacao, conexao com PostgreSQL e executor de migrations.
  • backend/config/migrations: scripts SQL que criam e evoluem tabelas como usuarios, produtos, pedidos, check-ins, pontos, cupons, Strava e imagens de perfil.
  • backend/controllers/handlers: camada HTTP. Recebe requisicoes, valida dados basicos e chama os servicos.
  • backend/middlewares: regras intermediarias, principalmente autenticacao via JWT.
  • backend/models: structs Go que representam entidades do sistema, como User, Product, Order, Coupon, CheckIn e PointTransaction.
  • backend/repositories: acesso ao banco de dados usando GORM.
  • backend/routes: registro das rotas publicas, protegidas e administrativas.
  • backend/services: regras de negocio, como compra, pontuacao, cupons, autenticacao e check-ins.

6. Principais pastas do frontend

  • frontend/src/pages: paginas da aplicacao, incluindo Home, Login, Cadastro, Produtos, Detalhe de Produto, Carrinho, Perfil, Pedidos, Check-in, Pontos, Cupons, Admin e callback do Strava.
  • frontend/src/components: componentes reutilizaveis, como layout principal, cards de produto, rotas protegidas e introducoes de secao.
  • frontend/src/context: estados globais de autenticacao, carrinho e tema.
  • frontend/src/services: funcoes que consomem a API, separadas por dominio: autenticacao, produtos, pedidos, check-ins, pontos e cupons.
  • frontend/src/lib: configuracao base do cliente HTTP.
  • frontend/src/utils: utilitarios e mapeamentos usados pela interface.
  • frontend/src/types.ts: tipos TypeScript compartilhados entre paginas, componentes e services.

7. Fluxos funcionais importantes

Cadastro e login

A usuaria cria conta ou entra com e-mail e senha. O backend retorna um token JWT, que o frontend usa para acessar rotas protegidas como carrinho, perfil, pedidos, check-in, pontos e cupons.

Compra e liberacao do Check-in Fitness

Clientes autenticadas criam pedidos a partir dos produtos do carrinho. Quando um pedido e confirmado como pago, o sistema marca a primeira compra da usuaria e libera a area de Check-in Fitness.

Check-ins, pontos e cupons

Cada check-in valido gera pontos. A regra atual limita a um check-in por dia por usuaria. Os pontos podem ser trocados por cupons, que ficam associados a cliente com status de uso.

Perfil e Strava

O codigo atual inclui campos e rotas para foto de perfil e integracao com Strava. Existem endpoints para iniciar login Strava, receber callback e atualizar foto de perfil da usuaria autenticada.

8. Rotas principais da API

  • Autenticacao: POST /auth/register, POST /auth/login, GET /auth/me, PATCH /auth/me/photo, GET /auth/strava/login, GET /auth/strava/callback.
  • Produtos: GET /products, GET /products/:id, POST /products, PUT /products/:id, DELETE /products/:id.
  • Pedidos: POST /orders, GET /orders/my, GET /orders/:id, GET /orders, PATCH /orders/:id/status.
  • Check-ins: POST /checkins, GET /checkins/my, GET /checkins.
  • Pontos: GET /points/my.
  • Cupons: POST /coupons, GET /coupons, POST /coupons/redeem, GET /coupons/my.

9. Como executar

Com Docker Compose

  • Copiar variaveis: cp .env.example .env.
  • Subir ambiente: docker compose up --build.
  • Frontend: http://localhost:3000.
  • Backend: http://localhost:8080.
  • PostgreSQL: localhost:5432.

Separado

  • Frontend: entrar em frontend, instalar dependencias com npm install e rodar npm run dev.
  • Backend: entrar em backend, preparar .env, garantir PostgreSQL ativo e rodar go run ..
